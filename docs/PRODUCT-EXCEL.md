# استيراد وتصدير المنتجات من Excel

من اللوحة ← المنتجات:
- **تصدير البضاعة:** ينزل ملف `.xlsx` بكل المنتجات، حتى المخفية، بغض النظر عن البحث والفلتر. صف لكل تركيبة، مع المخزون والمحجوز والمباع والمتاح والأسعار، وشيت للأكواد وتعليمات الاستخدام.
- **استيراد Excel:** تحميل قالب فارغ بعناوين عربية، واختيار ملف، ومراجعة الإضافات والتعديلات، ثم «تأكيد الاستيراد». المعاينة وحدها لا تحفظ أي بيانات.

## تعبئة الشيت

1. استخدم القالب، أو صدّر أحدث نسخة لتعديل منتجات موجودة. متغيرش عناوين الأعمدة.
2. كل صف يمثل لون ومقاس. كرر بيانات المنتج نفسها على كل صف تابع له. كود المنتج وكود التركيبة والرابط الإنجليزي لازم يكونوا فريدين.
3. المنتج الجديد: سيب المعرف والإصدار فاضيين. الموجود: احتفظ بمعرفه وإصداره من أحدث تصدير. الملف القديم يُرفض لو المنتج اتعدّل بعده.
4. اختار أكواد الأقسام والماركات والألوان والمقاسات من شيت «الأكواد». أضف أي اختيار ناقص من اللوحة الأول.
5. الصور: من صورة إلى 8، روابط HTTPS مباشرة أو مراجع `fs:` موجودة، بفاصل `|`. مراجع الصور في التصدير تشير لنفس المتجر؛ الصور المدمجة في Excel لا تُرفع. يمكن تعديل الصور من محرر المنتج.
6. «مخفي» و«مميز» و«جديد»: `1` أو `0`. الأسعار والأعداد أرقام بدون عملة أو صيغ. الوصف والإنجليزي والماركة والقسم الفرعي وسعر العرض وحد المخزون اختيارية؛ الفراغ يمسح قيمتها عند التعديل.
7. المخزون هو الإجمالي قبل خصم المحجوز، ولا يمكن أن يقل عن المحجوز. أعمدة المحجوز والمباع والمتاح للعرض فقط، والقيم الأصلية محفوظة.

الحد: **50 منتج و150 صف تركيبة و5 ميجابايت لكل استيراد**. التصدير الأكبر يمكن تقسيمه. الصيغة المدعومة `.xlsx` فقط، بدون تشفير أو صيغ؛ `.xls` وCSV غير مدعومين هنا. محتوى يبدأ بعلامة `=` يُصدر كنص صريح وليس صيغة.

## الحفظ والأمان

- لا حذف لمنتجات أو تركيبات غير مذكورة في الشيت.
- مراجعة كاملة للحقول والمراجع والتكرار، برسائل الصفوف. أي خطأ يمنع حفظ الملف كله.
- الحفظ في transaction واحدة تحت `catalogControl/main`، مع إعادة التحقق عند الحفظ ومنع استبدال تعديل أحدث؛ `auditLogs` وحركات `inventoryLogs` ضمن نفس المعاملة.
- المدير العام فقط. لا collections جديدة ولا تغيير في `firestore.rules` ولا كتابة في المشروع الحقيقي أثناء الاختبارات.
- معالجة ZIP/XML محدودة الحجم، والتحقق من CRC، وعدم تنفيذ صيغ أو ماكرو أو تحميل علاقات خارجية. ملفات XLSX المدعومة بالقيم النصية والرقمية فقط، وليس محرك Excel كامل.
- لا مكتبات موقع إضافية ولا npm أو build step. قراءة الملفات المضغوطة تحتاج متصفح حديث يدعم `DecompressionStream('deflate-raw')`.

## التحقق

```bash
node tools/check.mjs
CHROMIUM_PATH=/usr/bin/chromium node tests/smoke.mjs http://127.0.0.1:8080/
CHROMIUM_PATH=/usr/bin/chromium node tests/excel-format.mjs http://127.0.0.1:8080/
# بعد تشغيل وتفريغ محاكي demo-store طبقًا لـ FIREBASE_SETUP.md:
CHROMIUM_PATH=/usr/bin/chromium SDK_DIR=/workspace/store-test-tools/sdk BASE_URL=http://127.0.0.1:8080/ node tests/live-emulator.mjs
```

`tests/fixtures/*.xlsx` ملفات اختبار مستقلة أُنشئت بـ XlsxWriter 3.2.9: نصوص مشتركة مضغوطة، عربي، أكواد بصفر في البداية، نص يشبه الصيغة، وملف فيه صيغة مرفوضة. XlsxWriter ليس dependency للموقع أو لتشغيل الاختبارات. ملف التصدير اتفتح كمان بقارئ openpyxl 3.1.5 المستقل.

رحلة المنتج المستورد تشمل العرض والإضافة للسلة ومراجعة checkout. **إنشاء الطلب وتغيير حالته لم يُنفذا بعد**؛ المرحلة 6 ما زالت مؤجلة، فلا يمكن اختبار الطلب في اللوحة قبل تنفيذها.

نتائج التحقق للإضافة: `tools/check.mjs` **1059 ناجح / 0 فشل**، و`tests/smoke.mjs` **29 رحلة ناجحة** على الموبايل والديسكتوب، و`tests/excel-format.mjs` **6 فحوص ناجحة**، و`tests/live-emulator.mjs` **17 ناجح / 0 فشل** بما فيها دفعة 50 منتج و150 تركيبة في Firebase Emulator. تمت مراجعة صور `excel-buttons-*` و`excel-preview-*`، وإصلاح قص تعليمات المعاينة على الموبايل. الاختبارات كلها على بيانات تجريبية؛ المشروع الحقيقي لم يتغير.
